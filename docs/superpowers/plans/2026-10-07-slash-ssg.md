# slash-ssg Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar o template `packages/slash-ssg` no `slash-meta`: gerador de sites estáticos multipágina com Slash, com tabela de rotas, `<head>` por página, ilhas, pipeline de imagens (sharp), sitemap, dev server com live reload e um site de exemplo testado.

**Architecture:** Lógica pura em `src/lib/*-core.ts` (testada com `bun test`). O build (`scripts/ssg/build-site.ts`) faz o bundle de `src/client.ts` para o browser e de `src/lib/prerender.ts` para Bun (os dois com CSS Modules), processa imagens com sharp, executa o prerender (que importa `src/routes.ts`) e escreve `dist/`. O dev server roda esse build em subprocesso a cada mudança e avisa o browser por SSE.

**Tech Stack:** Bun 1.3.x, TypeScript, `@_bashell/slash` (workspace), `sharp`, Playwright, Biome.

**Spec:** `docs/superpowers/specs/2026-10-07-slash-ssg-design.md` (leia antes de cada tarefa; este plano argumenta a partir dele)

## Global Constraints

- Diretório do template: `/home/dev/Projetos/slash-meta/packages/slash-ssg`. Repositório git próprio (já iniciado, branch `main`). Trabalhe na branch `feat/slash-ssg`.

- `htmlString` trata como HTML já renderizado qualquer string filha que começa com `<`, e escapa as demais. Componentes devem retornar um único elemento raiz.
- Estilos: CSS Modules + `plugins/css-types.ts` (cópia do `slash-ssr`). Sem Tailwind.
- Mensagens de erro e textos do exemplo em português.
- Valores fixos do spec: porta `4000`; marcadores `<!--slash:head-->` e `<!--slash:app-->`; params `/^[a-z0-9-]+$/`; título `"{title} | {site.name}"`, exceto quando `title === site.name`; larguras default `[480, 960, 1440, 1920]`; qualidade default `{ avif: 50, webp: 75, jpeg: 80 }`; Open Graph JPEG com 1200px de largura (ou a original, se menor); saída de imagens `dist/_img/<nome>-<hash8>-<largura>.<ext>`; cache `.slash-cache/`; debounce do watch de ~100 ms; endpoint SSE `/__reload`.

## Review Focus

1. **Texto com caracteres especiais no `<head>`**: título ou descrição como `Clínicas & Saúde "Premium" <2026>` precisa sair escapado e com acentos intactos. Teste em `head-core` (Task 3).
2. **`baseUrl` com barra final** (`https://exemplo.com/`): canonical, `og:url`, `og:image` e sitemap não podem conter `//` duplo. Teste em `routes-core` (`absoluteUrl`, Task 2) e `sitemap-core` (Task 5).
3. **Nomes de imagem "humanos"** (`Mockup Clínica.PNG`, extensão maiúscula, espaços e acentos): devem ser processados e gerar URLs seguras (`mockup-clinica`). Teste em `image-core` (`slugifyImagePath`, Task 7) e `images-build` (Task 8).
4. **Props de ilha com `'`, `"`, `&`, `</script>` e unicode**: devem chegar idênticas ao browser. Teste de ida e volta em `island-core` (Task 4).
5. **URLs com query string** (links de campanha `/sobre/?utm_source=insta`) e sem barra final (`/sobre?utm=x`): devem servir a página ou redirecionar preservando a query. Teste em `serve-core` (Task 11).

### Task 8: Imagens, processamento com sharp

**Files:**
- Create: `src/lib/images-build.ts`
- Test: `src/lib/images-build.test.ts` (gera as fixtures com sharp em um diretório temporário; nenhum binário commitado)

**Interfaces:**
- Consumes: tudo de `image-core` (Task 7), `SsgError`.
- Produces:
  - `processImages(opts: { srcDir: string; outDir: string; cacheDir: string; config: ReturnType<typeof resolveImagesConfig> }): Promise<ImageManifest>`
  - `generateOgImages(manifest: ImageManifest, paths: Iterable<string>, opts: { srcDir: string; outDir: string; cacheDir: string; quality: number }): Promise<void>`
- Comportamento (spec, "Pipeline de imagens"):
  - aceita `jpg, jpeg, png, webp, avif, svg, gif`, com extensão sem diferenciar maiúsculas;
  - `hash` = 8 primeiros hex de sha256(bytes + JSON(config));
  - variações em `<cacheDir>/images/<hash>/`, copiadas para `<outDir>/_img/`; se o diretório do hash existe, não chama sharp;
  - `.rotate()` (respeita a orientação EXIF), `.toColorspace("srgb")` e sem `withMetadata`; PNG com `compressionLevel: 9`;
  - concorrência limitada a `os.availableParallelism()`;
  - grava `<cacheDir>/images-manifest.json`;
  - arquivo inválido → `SsgError` com o caminho e a mensagem do sharp.

### Task 11: Servidor estático, preview e dev com live reload

**Files:**
- Create: `scripts/ssg/serve-core.ts`, `scripts/ssg/serve.ts`, `scripts/ssg/build-queue.ts`, `scripts/preview.ts`, `scripts/dev.ts`
- Test: `scripts/ssg/serve-core.test.ts`, `scripts/ssg/build-queue.test.ts`

**Interfaces:**
- Produces:
  - `serve-core.ts`:
    - `resolveRequest(url: URL, exists: (relFile: string) => boolean): { kind: "file"; file: string; status: 200 | 404 } | { kind: "redirect"; location: string }`. Regras: `/` → `index.html`; `/x/` → `x/index.html`; `/x` → redirect para `/x/` + `url.search` quando `x/index.html` existe; arquivo existente → ele mesmo; caso contrário → `404.html` com status 404.
    - `renderErrorPage(message: string): string`: HTML com a mensagem escapada em `<pre>` e o script do EventSource (para recarregar quando o build for corrigido).
  - `build-queue.ts`: `createBuildQueue(run: () => Promise<void>): { trigger(): void; idle(): Promise<void> }`. Nunca roda dois builds ao mesmo tempo; gatilhos durante um build resultam em **um** build extra ao final.
  - `serve.ts`: `startServer(opts: { dist: string; port: number; dev: boolean; getError?: () => string | null }): { broadcastReload(): void; stop(): void }`. `GET /__reload` → stream SSE (apenas em dev). Em dev com `getError()` não nulo, respostas HTML viram `renderErrorPage`.
  - `preview.ts`: `startServer({ dist, port: 4000, dev: false })`.
  - `dev.ts`: build inicial e rebuilds via subprocesso `bun run scripts/build.ts --dev` (`Bun.spawn`, captura stderr); watch de `src/` e `public/` reaproveitando a estratégia de watch do `slash-ssr/scripts/dev.ts` (polling no Linux), com debounce de 100 ms → `queue.trigger()`. Sucesso → limpa o erro e chama `broadcastReload()`; falha → guarda o stderr como erro, imprime e chama `broadcastReload()`.
